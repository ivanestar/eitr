# Changelog

All notable changes to this project are documented here, newest release first, following
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0] - 2026-09-06

- **Added**: the site map, feature map and test conditions can be reviewed in their review file: tick `[x]` to approve, answer on the `Answer:` line, delete a test condition's line to cut it, correct any text in place. `scripts/apply-review.mjs` applies what it can exactly, hands everything else back to the assistant as corrections, and refuses a file rendered from an older JSON. Review files are no longer deleted after sign-off. See ADR 0015.
- **Added**: `scripts/corroboration.mjs` checks the site map and feature map against the independent records the project holds (server status, page markup, screenshot, traffic, per-role access). It flags a page the records disagree about, a rating lower than the page's calls or fields allow, and quoted evidence that is not on the recorded page. Every disagreement and how it was settled is kept in `artifacts/analysis/sensor-journal.jsonl`, and `report` shows how often each kind of record turned out right. See ADR 0016.
- **Changed**: a field meaning or constraint in the test conditions may claim `high` confidence only with a second independent source. The page inventory records headings. `auth-status.mjs` reads a saved session's expiry from the file and reports `session-expired`, and `/auth-setup` then recommends a fresh capture.
- **Fixed**: approving a test condition also clears `isSpeculative`, which the validator required and the skill never said.
- **Changed**: skill briefings and the pipeline's pre-flight notice print each heading on its own line with one blank line between blocks, bullets for what is worth knowing, and `[WARNING]` / `[NOTE]` labels for time and cost, contact with the live application, and where the person stays in control. The stage list keeps its descriptions in one column whichever stage is bracketed. The feature map review separates every role, feature, page and entity with a blank line.

- **Changed**: `/define-test-conditions` works per reviewed feature and starts from what the feature means. Before any condition, it records what the feature does, how it serves the application's confirmed purpose, what every field means and should obey (with where each constraint comes from and what the page enforces today), its dependencies, and the questions only a person can settle. Every parameter must stand on a field meaning. See ADR 0014.
- **Added**: every test condition says what it exercises (field, rule, behaviour, frame) and where its expected result comes from: a requirement, a person, research or the meaning of the feature checks correctness, while what the page states or was seen doing only guards against regression. The review marks which is which. Anchors must point at something that exists.
- **Added**: conditions are ranked as likelihood times the feature's impact (P1-P3) by the generator. Nothing is removed for ranking low; a condition that may be a check for its own sake carries a visible note, and the person decides. New techniques: `decision-table` and `error-guessing`.
- **Added**: `scripts/field-probe.mjs` types values into a field and reads back what the page did, then restores it. It works only when the crawl boundary allows interaction, and submits only when the boundary allows any action on an application a person said is not production. It applies `minlength` and `maxlength` itself, since browsers check them only on typing - live-observed passing five digits into a ten-digit field.
- **Added**: `scripts/test-research.mjs` keeps research per kind of feature, on by default: at least five sources from four sites, every finding citing its sources, and no query naming the application. Without web access, research is recorded as skipped with the reason.
- **Added**: `scripts/test-analysis-plan.mjs` decides the test basis (a crawled application, or one with requirements, tickets or code as evidence - it asks when both are present) and computes which feature is at which step. A documents-only basis says plainly it is not built yet.
- **Changed**: `/map-site` asks what kind of application it is before the crawl boundary, and never offers a boundary that submits, creates or deletes on production. `/map-features` no longer asks again once it is recorded.
- **Changed**: `test-conditions.json` moved to schema version 3; an older file is treated as absent and regenerated.
- **Fixed**: a form field's nearby-text hint no longer takes a neighbouring link or button for its label - a unit converter's measure list had been hinted "Back to Home".

- **Fixed**: `/map-site` stops when the site is not letting it in, instead of mapping the refusal. `page-inventory.mjs record` rates each page's `access`: a Cloudflare challenge the browser did not get past, a refusal status on a near-empty page, or the identical page at two addresses. `crawl-budget.mjs` halts the pass and says what the human can do about it on a bot check, a first page that is a refusal, an unreachable host or an untrusted certificate, a refusal page served at every address, or three rate-limit refusals in a row. The same page at two addresses without a refusal is only a warning. On a 50-site run, 12 sites had put a Cloudflare check, a block or error page, a country picker or a national certificate the browser does not trust where the site should be.
- **Fixed**: the page inventory reads inside open shadow roots and same-origin frames, and lists the cross-origin frames and drawing surfaces it cannot read into. A government portal's home page had recorded zero controls while 118 sat inside web components.
- **Added**: a header, footer or sidebar the site never marked up is found by repetition. `shared` splits each page into top-level blocks and treats a block that recurs under the same labels on at least 30% of routes as the site frame (`foundBy: "repetition"`), except where the page marks up that region itself - a consent banner above a real `<header>` is not a second header. 19 of 39 reachable sites in the same run had no frame found.
- **Fixed**: shared widgets are matched by similarity (80% of their controls in common) rather than exact identity, so a header carrying breadcrumbs or a current-page marker is still one header - MDN's held 119 controls on one page and 122 on the next.
- **Added**: `classify` covers what code cannot place in every language and markup. It asks the crawling assistant about elements that react to the pointer but are no control in the markup (a calculator's 51 keys drawn as spans), and about button labels outside the English output words. Every answer is checked against the numbered list, control names come from the page, decisions are remembered for the rest of the crawl, and the run summary counts them. Links to documents, spreadsheets and archives count as downloads in any language, and `<summary>` is recorded as a control.
- **Fixed**: overlays in the visitor's language can be closed. The ledger recognises a lone cross, a dismiss attribute, or a close class on a control that shows no words. Labels it cannot read ("Закрыть", "닫기") go to the assistant through `overlay-ledger.mjs label`, and the ledger still refuses any control its own list knows commits to something. About 15 of the 50 sites opened a consent or promo overlay, several in a language other than the page's.
- **Fixed**: the overlay ledger matches its close words as whole words. The single-letter entry "x" matched the start of any word, so a product link "... Huawei Pura XMax" counted as a close control, and "See Xbox games" would have been pressed as one.
- **Changed**: a form field's nearby-text hint also reads a label cell beside it or a caption above its wrapper.

- **Added**: test conditions for what a page's output must obey. `property` holds over one run's whole output (`count-matches-request`, `all-unique`, `format-conformance`, `covers-all-pairs`, `output-matches-display`, `persists-across-navigation`); `metamorphic` links two runs (`round-trip`, `idempotence`, `symmetry`, `permutation-invariance`). A generator, converter or formatter has no example answer to write down in advance, but its output still follows rules - checked live on a GUID generator asked for 500: 500 listed, all distinct, all UUID v4. `/design-test-cases` and `/automate-test` turn each into one assertion over the whole output.
- **Added**: every copy, export or download control on a page needs a condition checking what it delivers, or an exclusion with a reason, and the gate refuses a page where one goes unchecked. A live toolkit had an Excel export and a copy button nothing looked at.
- **Added**: the site frame's own fields - a language switcher, a theme toggle - are tested once, on the route named in `frameRouteId`, including whether the chosen setting survives a reload and a move to another page. The gate warns when no route carries them.
- **Fixed**: every field on a page is accounted for before its test conditions are generated. `/define-test-conditions` starts each route from the crawl's inventory, and its gate refuses a route that leaves a field neither a parameter nor excluded with a stated reason (`result-output`, `duplicate`, `disabled`, `needs-button`, `off-limits`). Fields of the site frame - a language switcher, a theme toggle - are no page's parameter. A live run had recorded two parameters on a GUID generator carrying seven fields, and the header's language switcher as a parameter on 13 of 28 pages.
- **Fixed**: the gate checks what the extraction claims against what the page carries: select and radio options come from the inventory, an `html5-constraint` rule has to match the field's real attribute, a parameter's kind has to match the field's type, and a number field can no longer carry a non-numeric sample, which the browser would empty. The review lists every field left out and why.
- **Fixed**: the crawl records what is actually on each page. `scripts/page-inventory.mjs` collects every landmark and control in the browser - role, accessible name, type, HTML5 constraints, options, and whether it sends a result elsewhere (copy, export, download) - into `artifacts/site-map/inventory/<routeId>.json`, and a route's `components` lists its own fields and buttons by role and name. A live 28-route run had recorded tag names (`a`, `button`, `select`) on every page.
- **Fixed**: shared widgets are found by script. A header, navigation, footer or sidebar region with the same controls on two or more routes is named in `sharedWidgets` and described in `inventory/shared.json`; the same live run now yields a header and a footer shared by all 28 routes, where it had found none. `/map-site` no longer writes widget code while mapping - widgets are built with the Page Objects.
- **Changed**: `contentHash` is computed by the script from the page's structure - title with digits normalized, regions, and each control's region, role and type - so a pagination chain still repeats it and the crawl budget still stops the chain early.
- **Added**: `pom-engineer` and `/scan-and-generate-pom` reconcile a Page Object against the route's inventory, build shared widgets from `shared.json`, and flag controls that have no accessible name.
- **Fixed**: `/map-features` decides a page's criticality by what breaks, not by what kind of page it is. "Tools and utilities" were listed as a `medium` category and "linked from the navigation" as a `high` shortcut, so a live run put every tool on a 28-route toolkit in one tier. The checklist now also asks whether a person acts on a result they cannot check by hand - a generated test design, a calculation - which is what separates a pairwise generator from a character counter.
- **Fixed**: a generated test condition never combines two invalid values. The first value an application rejects hides what it does with the second, so each invalid value is now paired only with valid values of the other fields, and a valid combination counts as covered only in a condition where every value is valid - the rule PICT applies to its negative values. A live run had 27 of 155 combinations carrying two.
- **Changed**: every test condition names what a person should see. Each partition records its expected outcome, each boundary what is accepted at the limit and what is refused past it, and conditions are built from those (`With count="5": exactly 5 GUIDs are listed in the result`), replacing "Verify the page correctly handles ...", which left a test case nothing to assert. The validator rejects stock phrases such as "correctly handles" and "works as expected" in every description and outcome, including the conditions the model writes itself.
- **Fixed**: a value is invalid only when the page says so. Invalid partitions and boundaries have to quote the rule they rest on - an HTML5 constraint, a label, the offered options, or a person - and a placeholder such as "e.g. 20" is refused as one. Selects and radio groups record the options they offer, so an offered option can no longer be marked invalid; a live run had turned a unit converter's own `speed` option into a negative case and a placeholder into a maximum.
- **Added**: an invalid value that a select, radio or checkbox cannot produce carries an execution level - `dom`, set by script past the control, or `api`, sent to an endpoint the crawl saw the route call. `compose-journeys.mjs` routes the condition by it, and `/design-test-cases` and `/automate-test` know how to write and automate the resulting `Force the [X] field to <value>` step.
- **Changed**: `test-conditions.json` moved to schema version 2; an older file is treated as absent and regenerated.
- **Fixed**: generated skills and rules no longer show a garbled three-character sequence where a dash was meant.
- **Changed**: TypeScript + Playwright is the only stack generated and supported. Python, C#, Java and Cypress are frozen - their generators, templates and linters are still in the repository and still work, but nothing offers them, `eitr generate` refuses them, `eitr doctor` no longer reports on toolchains they need, and their tests do not run. One stack carried all the way to a verified working suite is worth more than four carried most of the way, and Playwright's own ecosystem is not evenly distributed either: the test runner, UI mode, HTML reporter and VS Code extension exist for Node only. See `docs/architecture/decisions/0013-freeze-non-typescript-stacks.md`.
- **Changed**: the parity standard lost its language axis and kept every other one - a capability still has to land across every AI assistant, CI provider and TMS it applies to.
- **Changed**: `eitr doctor` reports what generating and running a project actually needs, and now checks for the `gh` and `glab` CLIs that `/auth-setup` uses to push CI secrets - a missing one names the manual path rather than reading as an error.
- **Changed**: CI dropped the Maven, Gradle, NuGet and pip caches, and the nightly pairwise matrix went from 16 combinations to 6 that vary framework, UI library, CI provider and AI assistant instead of language.
- **Removed**: `artifacts/analysis/business-intent.json`, along with its schema and validator. It held a per-route feature label plus a criticality tier - the transpose of the grouping the feature map already carries, since routes sharing a label are a feature. Two files described the same routes from two angles, with two review gateways and one axis expressed at two granularities that could disagree.
- **Changed**: `/map-site` is now purely a crawl, and its one deliverable is the route list - which it now actually presents for review, something no stage did before. Working out what each page is for moved to `/map-features`, which produces one artifact holding the features, the entities behind them, and every mapped page's own feature and criticality. One stage, one artifact, one review.
- **Changed**: a page carries a `featureId` rather than a feature name, so renaming a feature at sign-off renames it in one place. `derive-feature-map.mjs` is what turns the label the analysis wrote into that id, and it reads the label back off the feature on a re-run - without that, a second pass silently regrouped every page by its path.
- **Added**: the feature-map review now shows each page under its feature with the criticality it was given and the sentence justifying it, plus a **Pages no feature claims** section - a page nothing claims is a page nothing downstream will ever test, and nothing else in the pipeline said so.
- **Added**: `scripts/map-features-questions.mjs` asks what kind of application this is and what it is for. Both questions moved off the crawl, where neither could be answered before something had read the pages, and where the answers changed nothing about how the crawl ran.
- **Added**: every skill now opens by saying what is about to happen - what it will produce, how, why, and what is worth knowing first (how long it runs, that it touches the live application, that no code is written without approval). The text lives in `scripts/skill-briefing.mjs` rather than in each skill's prose, so it cannot shorten under pressure into a stage name and nothing else.
- **Changed**: options at those confirmations name their own outcome ("Start the crawl" / "Not now") instead of yes and no, and a stage running inside `/ground-zero-setup` prints its briefing without asking again - the chain's own gate already carries that decision, and two questions for one decision is friction rather than safety.
- **Changed**: `/ground-zero-setup`'s stage gate now shows what the next stage will actually do before asking you to approve continuing to it. Agreeing to "continue to /map-features" previously meant agreeing to a command name.
- **Fixed**: a review artifact written to a file is now always presented with its path on its own line. A question about `feature-map.md` arrived without saying where `feature-map.md` was.
- **Added**: the crawl records every modal, drawer, consent banner and native dialog it meets - what raised it, what it contains, and its own screenshot - and has to say how it closed it, re-checked rather than assumed. A dialog left open blocks nothing at the protocol level; it just covers the page, so every later click lands on a backdrop and explores nothing, which is what a crawl that appears to hang is usually doing.
- **Added**: `scripts/overlay-ledger.mjs` owns how an overlay may be dismissed. Under a read-only boundary that is a reload and nothing else, since a keystroke is still an interaction; at no boundary does an automatic plan contain a control that commits to something (`Accept`, `OK`, `Confirm`, `Delete`), because nothing in a label separates an informational OK from the OK on a confirm-before-deleting dialog. When only permission is missing it asks once per overlay rather than once per page, and when nothing works it flags the route `blocked-by-overlay` instead of looping.
- **Fixed**: a native `alert`/`confirm`/`prompt` no longer stalls a crawl. Playwright auto-dismisses one only while no `page.on('dialog')` listener exists, so a handler that inspected a dialog without answering it hung the action that opened it, permanently and silently.
- **Changed**: a route's saved screenshot is now taken after any overlay has been cleared, so the visual baseline shows the page instead of the same consent banner across forty of them.
- **Added**: the crawl now reads each page's screenshot as it goes, so navigation that carries no `href` — a button, an image menu, a link that navigates by script — stops being invisible to it. A worker looks at numbered marks drawn over the page's own elements and reports which ones the crawl missed; anything carrying a real URL joins the same pass, and anything that would need a click is collected into one question asked at the end rather than pressed on the spot.
- **Changed**: the crawl's time bound measures the gap since the last new route instead of the time since it started. Total elapsed time is a fact about the machine and the network rather than the application, so it cut a large or slow site off half way and left a map somebody had to notice was incomplete. A crawl still finding pages now runs as long as it needs to; one that has genuinely wedged is stopped after ten idle minutes, sooner than the old thirty-minute ceiling caught it. `maxPages` remains the global runaway stop.
- **Fixed**: the markup heuristics that guess a page's state can no longer record a failure. Matching a token in a URL and counting a page's controls are proxies, and a measured crawl of 51 routes found them wrong about 14 of them — a working sign-in form was recorded as a broken page because its URL contained "login". They now raise a flag; whether a route is an auth wall, forbidden or an error is decided by the status the server returned, or by the visual pass.
- **Added**: a redirect is recorded instead of being silently followed. The destination owns the route entry and the requested path is kept in `redirectedFrom`, so a route reachable only as a redirect target stops being invisible and a test that hits the old path has somewhere to look. A redirect off the application is reported rather than mapped.
- **Fixed**: a navigation candidate with no URL is now hovered before it is pressed. A live run against a jQuery UI menu found the visual pass naming the right element and a press revealing nothing at all — that whole class of menu opens on hover. Hovering also changes no state, so it costs the human's permission nothing.
- **Added**: `scripts/visual-copilot.mjs` decides what any of that is allowed to change. A mark the page never had is dropped, a proposed URL still goes through the frontier gatekeeper, "it is still loading, re-shoot it" runs out after two retakes, and a screenshot can never be the evidence behind a claim that a route is not real.
- **Added**: a page still rendering when its screenshot was taken is re-shot and, if it still has not settled, flagged as such — the crawl no longer records a spinner as an empty page. `visualTriage.source` says whether a worker or the cheap markup heuristic classified a route, which are worth very different amounts.
- **Added**: `map-site-status.mjs reset-screenshots` clears the screenshot directory at the start of a `create` pass, so it holds one crawl's images rather than several — previously 1239 files backed a 44-route map. It refuses while another crawl is running.
- **Fixed**: `site-map.schema.json` rejected `discoveryMethod`, which the site map has always been required to carry and which decides whether a route may be flagged as a phantom. The validator now checks its value too.
- **Fixed**: a question offering a single choice no longer breaks the assistant's choice tool, which requires at least two options and rejects the call outright. `/map-site`'s core-purpose confirmation hit this routinely, since the step before it deliberately produces one candidate whenever the evidence supports one reading — it is now asked as a confirmation with an explicit "I will describe it myself" alternative.
- **Fixed**: the generated C# `Dockerfile` referenced `mcr.microsoft.com/playwright/dotnet:v1.62.0-jammy`, which has never existed — that image publishes only `noble` and `resolute` variants. Now points at `-noble`.
- **Added**: `npm run check:playwright` reports whether each language's pinned Playwright version has fallen behind its registry and whether a matching container image exists yet, and fails outright on a rendered image tag that does not resolve. The pins stay exact on purpose: Playwright's browser binaries are built for one specific release, so a floating range breaks the container image pairing.
- **Fixed**: generation no longer fails with `No matching version found for playwright@<version>` when npm's cached package listing predates the pinned Playwright release. `--prefer-offline` served that stale listing; a failed install now retries once with `--prefer-online`.
- **Fixed**: the crawl's traversal bounds are enforced by `scripts/crawl-budget.mjs` instead of by skill prose. A live run followed a pagination chain 5441 times past a documented 500-page ceiling, wrote 657 MB of screenshots over 31 minutes, and produced no site map at all.
- **Added**: `scripts/crawl-budget.mjs` — URL canonicalization, a cap on concrete URLs per canonical route template, rejection of cross-origin links, non-`http(s)` schemes and links to files rather than pages, and the crawl's own progress line so a long crawl stops looking hung.
- **Added**: the crawl recognises a trap on its third page instead of at the page ceiling. Three pages rendering identical structure under one route template stop that template outright; the same structure under several different templates warns instead, since canonicalization deliberately keeps `/blog/page-2` and `/blog/page-3` apart and that shape can also be a legitimate generic empty state. Warnings surface to the human as they happen, not in the final summary.
- **Added**: the two-viewport-scroll ceiling is enforced by `crawl-budget.mjs scroll` rather than described in prose. An infinite feed never changes its URL, so no other guard in the crawl can see it.
- **Added**: `scripts/artifact-journal.mjs` — any stage that fans out over many units now commits each one to an append-only journal as it finishes and folds the artifact from it at the end, so an interrupted run keeps its work and resumes instead of restarting.
- **Added**: `E2E_DEBUG=1` records what each helper script was asked and answered to `artifacts/.debug/`, readable with `node scripts/debug-log.mjs tail`. Off by default.
- **Added**: `map-site-status.mjs prune-screenshots --orphaned` clears screenshots stranded by a crawl that died before writing a site map, which the evidence-based prune cannot touch. Mode resolution now reports that count instead of a bare zero.
- **Changed**: the TypeScript stack pins Playwright 1.63.0. Python, Java and .NET stay at 1.62.0 until their own registries publish 1.63.
- **Added**: `/map-features` and `artifacts/analysis/feature-map.json` — a stage between the site map and test conditions that groups routes into features and records the entities an application works with, what can happen to each one, its lifecycle, and the links between them. Everything derived from a path or a field name is marked as inferred, and nothing downstream treats the file as ground truth until every feature and entity has been approved.
- **Added**: state transition testing and use case testing. Both need a model of what an entity's life looks like, which no per-page analysis can produce; they generate from reviewed entity lifecycles and are simply absent on a project without one.
- **Changed**: a test case's `layer` (`e2e`/`api`/`ui-only`) is now three separate fields — `testInterface` (`ui`/`api`), `breadth` (`targeted`/`e2e`), and `level` (`integration`/`system`). The old field mixed an interface, a breadth and a reason into one vocabulary, so "is this an API test?" could not be answered without parsing it.
- **Changed**: `e2e` means a journey that walks a feature across the routes it spans, not a thorough test of one screen. A route-keyed pipeline could not express that what one page creates turns up on the next; `test-cases.json` is keyed by journey now, and a journey carries a list of routes.
- **Changed**: low impact selects the cheapest interface that can check a route rather than fewer tests — an API call where a contract exists, the UI otherwise — and keeps that route out of end-to-end walks.
- **Changed**: acceptance is never derived. It says who validates a release and against what, which nothing here can observe, so it is recorded only when a person states it.
- **Added**: Test closure is a real roadmap stage — `coverage-status.mjs` already computed its state — plus an exit criterion for a multi-route feature with no test that walks it, the gap route-level coverage is blind to by construction.
- **Added**: `validate-api-contracts.mjs` reports two non-fatal observation warnings: a 2xx contract with no recorded response shape, and a crawl where almost no route contributed a call. One contract across 62 routes previously read exactly like an application with no API surface.
- **Added**: role-aware crawling — `/map-site` can crawl as several captured role sessions, records `crawledAsRoles` and a per-route `access` map in the site map, confirms what each role is actually for with the human, and turns an observed access difference into a `permission_denied` test condition instead of a guessed one.
- **Added**: seven checkable assertion rules in `/automate-test` and `assertion-auditor` — two independent channels for any state change, the negative space on any rejection, a direct request to a protected resource on any auth boundary, and a real `response.status()` where the behavior under test is an HTTP outcome.
- **Added**: `scripts/render-review-artifact.mjs` — every stage's review artifact is rendered from its own JSON rather than composed by the model, and anything past 10 entries is written to a file instead of scrolling past the top of the terminal.
- **Added**: CPOM linter Rule 7 across TypeScript, Python, Java, and C# — a credential literal typed into a credential field in a spec fails the lint, with `@allow-credential-literal: <reason>` for the one legitimate case, a deliberately wrong value in a rejection test.
- **Added**: `scripts/env-role-stubs.mjs` and `eitr auth --role <name>` — one `E2E_<ROLE>_USERNAME`/`E2E_<ROLE>_PASSWORD` slot per role in `.env`, and that role's own session file.
- **Changed**: `/auth-setup` asks whether the app has a login at all before explaining and asking approval for the capture procedure, and its role question offers the real options (no separate roles, one role, all of them now, some of them now).
- **Changed**: the browser capture step always prints the command for the human to run themselves, never runs it as the assistant — an assistant cannot verify that a window it opens reaches the human's screen, and the command blocks for the whole login.
- **Fixed**: `eitr auth` now accepts `--save-har <file>`, so the CLI wrapper `/auth-setup` recommends can satisfy the login network-observation step without falling back to a raw `playwright open` command.
- **Added**: `scripts/coverage-status.mjs` answers "is this suite done yet" from the artifacts alone — every high/medium-impact route has an automated test, every drafted test case was actually automated, every route with approved conditions got a test case, every endpoint seen in real traffic has an API-level test, every active route is classified. It names the specific gaps rather than counting them, and reports rather than gates: a team can knowingly ship with a gap, they just cannot ship without seeing it.
- **Changed**: `/automate-test` orders a batch by route impact, highest first. A large batch does not reliably finish in one session, and the ordering alone decides which tests exist when it stops.
- **Changed**: impact is decided by what a failure actually costs rather than by keyword matching — each level now leads with the consequence it describes, the keyword lists are explicitly fast paths that lose to the consequence when they disagree, and `medium` is a definition in its own right instead of the bucket everything unmatched fell into.
- **Added**: generated `CONVENTIONS.md` lists the project's own artifacts and deterministic helper scripts, so an assistant checks what is already recorded before asking or inferring it again — with the two rules that govern all of them: nothing is authoritative until a human reviewed it, and an absent record means "nobody established this yet", never "this is false".
- **Changed**: the pipeline roadmap marks the current stage with brackets alone, dropping the trailing "you are here" that restated them and pushed the line past the terminal width.
- **Changed**: route criticality is three levels (`high`/`medium`/`low`) instead of four. The `critical` tier above `high` changed nothing anywhere — the only mechanical consumer gates on "not medium and not low", so the two were indistinguishable in code, and both drew the same condition volume — while costing real inference effort and review attention. It is the impact axis of risk, and is now named as such.
- **Added**: `testTypes` in the app profile records which test types are actually in scope, defaulting to functional only. The default was previously implicit, which made "nothing checks accessibility" indistinguishable from an oversight. A new type is an entry plus a rule for what it contributes at the test-condition stage; no pipeline stage branches on a closed list of type names.
- **Added**: `artifacts/analysis/app-profile.json` — a durable record of the facts about an application that nothing else stores and no re-run can rediscover: what kind of application it is (production, sandbox/demo, internal tool), the crawl boundary a human set, and the domain knowledge a person volunteered. Read and validated through `scripts/app-profile.mjs`. It holds no copy of anything that already persists elsewhere (routes, confirmed purpose, observed endpoints stay in their own artifacts and are only pointed at), and it is optional enrichment for every reader — a skill that finds nothing in it asks the human exactly as before, so no skill becomes dependent on another having run.
- **Fixed**: a route is no longer reported as "possibly not real" without evidence — `httpStatus` is now part of the site-map schema (it was only ever mentioned in prose, so recording it would have failed validation), 401/403 marks a route as protected rather than phantom, and `validate-site-map.mjs` rejects a phantom flag on a nav-reachable route that has no recorded 404/410 behind it.
